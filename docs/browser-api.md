# Browser-safe HTTPS API (#130)

## Decision

A new `workstream-api` crate exposes a versioned HTTPS facade for browsers
and wallets. It is a **read/forward** boundary, never an authority:

- **Envelope.** Every response carries `api_version`, `request_id`, `network`
  (chain id), `read_height`, `indexed_height`, and either `data` or a stable
  string-coded `error`. A failure never emits `data` and vice versa.
- **Keys stay client-side.** The only write is `POST /v1/submit`, which accepts
  the canonical JSON bytes of an **already signed** transaction. The node
  reuses `SubmitTxRequest::validate` and `workstream_tx::TxValidator` before
  forwarding to the single writer. There is no field for a signing key,
  witness, blinding factor or payload in any request.
- **No privileged surface.** There is no DA post, P2P publish, proof job,
  grant or database endpoint. Projection rows are read hints; the verifier
  journal remains the authority and can reject an action a stale projection
  appears to allow.
- **Transport.** A rustls **TLS 1.3 server-auth** listener using the node
  identity's `cert.der`/`key.der`, separate from the internal mTLS sockets.
  Browsers present no client certificate. The listener binds loopback by
  default; `WORKSTREAM_API_PORT` enables it and `WORKSTREAM_API_ORIGINS` is a
  comma-separated exact-origin CORS allowlist (empty by default).
- **Session + idempotency.** `POST /v1/session` issues an opaque, expiring
  Bearer token (scoped to idempotency keys, granting no on-chain authority).
  `X-Request-Id` is echoed and cached per session; reusing an id with a
  different body returns `DUPLICATE_REQUEST` rather than applying twice.
- **Headers and limits.** Fixed security headers (`CSP`, `nosniff`,
  `X-Frame-Options: DENY`, `no-store`, HSTS), no wildcard origin, no
  `Allow-Credentials`, and a 256 KiB body limit.

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| POST | `/v1/session` | Issue short-lived session token |
| POST | `/v1/submit` | Submit signed transaction bytes |
| GET | `/v1/receipt?tx_hash=0x…` | Verified receipt lookup |
| GET | `/v1/chain` | Verified tip + projection cursor |
| GET | `/v1/tasks` | Work-item page (cursor/limit) |
| GET | `/v1/reviews` | Review queue page |
| GET | `/v1/receipts` | Verified receipt page |
| GET | `/v1/events` | Projection event page |
| GET | `/v1/openapi.json` | OpenAPI 3.1 document |

## Client generation

`crates/workstream-api/client/openapi.json` is emitted from the Rust
`openapi::document()` via `cargo run -p workstream-api --example dump_schema`.
An OpenAPI test asserts the checked-in schema equals the generator, so the
Rust DTOs and the TypeScript client cannot drift silently. The TypeScript
client makes no signing key material part of its surface.

## Cross-language agreement

`crates/workstream-api/testdata/vectors.json` is shared by a Rust unit test
and `client/test/vectors.test.ts` (`npm test`). They prove agreement on the
Ed25519 public key, a deterministic signature, and the domain-separated hash
used for stable request/correlation ids. The browser verifies the Rust-produced
signature with WebCrypto.

## Authority and freshness

`read_height` is the verifier's locally verified tip; `indexed_height` is the
projection cursor. `ChainData.stale` and `PageData.stale` are true when the
projection lags. A stale projection is visible but never authoritative: an
action apparent in a read model is still rejected by the verifier if it is not
in the canonical chain.

## Residual gaps

- Loopback-only in this iteration; exposing a public listener needs an
  operator-managed certificate chain and DNS, not a wildcard CORS.
- Sessions are in-process: a multi-replica deployment needs a shared store or
  sticky routing, and a restart clears sessions (clients re-issue).
- No hosted browser conformance suite is wired into CI; the TS vector test and
  Rust contract tests are the local evidence.
- The OpenAPI document is generated by Rust and checked in; a real codegen
  step (`openapi-typescript`) can replace the hand-mirrored TS types later,
  guarded by the same schema-equality test.
