# Private evidence objects (#133)

Set `WORKSTREAM_EVIDENCE_DIR` to a dedicated service-owned 0700 directory and configure workspace login on the HTTPS listener. Use one store per chain and trusted issuer. Never serve the directory as static files. The single-node backend keeps bytes in `objects.sqlite`; evidence is not published to DA or replayed by validators. Protect the volume and backups with host encryption. There is no hosted bucket or KMS integration.

The operator installs workspace grants in this private database: insert `(subject, task, digest, operation)` into `grants`, with the exact authenticated subject, lowercase 64-hex task ID, SHA-256 of the exact object bytes, and either `upload` or `read`. Use bound parameters. No HTTP route can install a grant. On-chain grants and workspace file access have separate lifecycles.

* `POST /v1/evidence/{task}/{digest}/upload`: send raw bytes and a workspace Bearer token. The default body cap is 256 KiB. Only a matching grant and digest can store the bytes. Retry with identical bytes is idempotent. The JSON acknowledgment is `Uploaded` and contains the task and digest. It is not a chain receipt. Use the same task and `content_hash` in `BundleAdmitPayload` and the signed `SubmissionCreatePayload`. Check the signed transaction receipt separately for verification.
* `POST /v1/evidence/{task}/{digest}/link`: requires a live workspace login and an exact read grant. Returns a relative bearer URL and a 60-second lifetime. A new link replaces any previous link for that subject/object. Revocation by deleting a read grant prevents subsequent issuance; an already issued link remains usable until its recorded expiry unless its ticket is deleted. A downloaded copy cannot be recalled.
* `GET /v1/evidence/download/{token}` returns an attachment only after checking token hash, expiry, and stored bytes against their digest. Treat the URL as a credential. Disable URL/body logging at external proxies; the application logs neither. The content digest is public if submitted on-chain; do not assume it conceals low-entropy content.

Objects persist across node restart until operator deletion; link expiry is not deletion. To retire an object, use one operator transaction with `PRAGMA foreign_keys=ON` to delete its grants, tickets, and object row. Apply retention to backups separately. SQLite secure deletion does not guarantee physical erasure on snapshots or SSDs. Monitor volume capacity and restrict grants to expected objects.
